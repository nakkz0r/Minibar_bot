## ЧТО ЭТО ЗА ПРОЕКТ

Telegram-бот для учёта мини-баров в отеле (Батуми, Грузия). Пользователи: горничные (проверяют номера), супервайзеры (смотрят отчёты), администратор (настраивает).

Как работает смена:
1. Горничная нажимает кнопку «🏨 შემოწმება» (или /start) → вводит номер комнаты (например 605) → выбирает статус кнопкой → если что-то выпито, отмечает товары в инлайн-каталоге → отправляет фото мини-бара.
2. Бот сохраняет проверку в базу и шлёт отчёт в рабочий Telegram-чат (REPORT_CHAT_ID): комната, статус, что израсходовано, сумма к оплате гостем, кто проверил, когда + сводка по всем номерам.
3. Вечером бот сам (или супервайзер кнопкой «📥 Excel») шлёт Excel-отчёт смены.
4. Утром бот сам (или админ кнопкой «🗑 ცვლის დახურვა») закрывает смену: итоги в историю, база в архив, список проверок очищается.

Интерфейс двуязычный: грузинский (основной) + русский в скобках. НЕ УДАЛЯЙ грузинские тексты.

## БАЗА ДАННЫХ (SQLite, файл minibar.db)

Таблица `rooms` — проверки текущей смены (одна строка = одна комната):
- `room_number` TEXT PRIMARY KEY — номер комнаты, строка ("605")
- `status` TEXT — статус, ровно один из: "შევსებულია" (заполнен), "არ არის შევსებული" (не заполнен), "ცარიელია სტუმარმა ითხოვა გამოტანა" (пустой), "Out of order"
- `details` TEXT — человекочитаемый текст расхода ("გამოყენებულია: Wine: 1, Chips: 1")
- `photo_id` TEXT — Telegram file_id фото ("" если нет)
- `json_details` TEXT — расход в JSON: `{"Wine": 1, "Chips": 1}` — ПО НЕМУ считаются все цифры
- `photo_type` TEXT — "photo" или "document"
- `checked_by` TEXT — имя сотрудника из Telegram
- `checked_at` TEXT — время "09.08.2026 14:35" (Тбилиси, UTC+4)

Таблица `catalog` — ассортимент мини-бара:
- `id` INTEGER PK, `name` TEXT UNIQUE, `qty` INTEGER (эталон в 1 номере), `position` INTEGER (порядок), `price` REAL (цена в лари, 0 = без цены)

Таблица `hotel_rooms` — полный список номеров отеля (для /remaining): `room_number` TEXT PK

Таблица `history` — итоги закрытых смен: `id`, `closed_at`, `rooms_checked`, `total_units`, `total_amount`, `consumed_json`, `staff_json`

ВАЖНО: ключи в `json_details` и `consumed_json` — это НАЗВАНИЯ товаров из `catalog.name`. Поэтому названия товаров нельзя менять напрямую UPDATE-ом — только через команду /renameitem, которая мигрирует и данные.

## ЖЕЛЕЗНЫЕ ПРАВИЛА — НАРУШАТЬ НЕЛЬЗЯ НИКОГДА

1. **СЕКРЕТЫ.** Никаких токенов, паролей, ключей, реальных ID в коде или в .env.example. Только `os.getenv(...)`. Если увидишь секрет в коде — скажи мне, это авария.
2. **ЭКРАНИРОВАНИЕ.** Любой текст, пришедший от человека или из базы, при вставке в сообщение бота оборачивай в `esc(...)`. Сообщения отправляются с parse_mode=HTML, символы `<`, `>`, `&` без esc() ЛОМАЮТ отправку. Правильно: `f"Номер {esc(room)}"`. Неправильно: `f"Номер {room}"`.
3. **SQL.** Только параметризованные запросы со знаками `?`: `conn.execute("... WHERE name = ?", (name,))`. НИКОГДА не подставляй переменные в SQL через f-строку.
4. **ASYNC.** Все хендлеры `async def`. Долгие операции (сеть, генерация файлов) — через `await asyncio.to_thread(...)`. Фоновые задачи — ТОЛЬКО через `schedule_bg(...)`, не голый `asyncio.create_task` (задачу без ссылки убивает сборщик мусора).
5. **ДЛИННЫЕ СООБЩЕНИЯ.** Любой текст, который может быть длинным (списки номеров!), отправляй через `answer_chunked` / `send_chunked`, не через голый `message.answer`.
6. **ГРУЗИНСКИЕ СТАТУСЫ.** Строки STATUS_FULL, STATUS_NOT_FULL, STATUS_EMPTY и тексты кнопок статусов — это КЛЮЧИ ДАННЫХ в базе. Менять их нельзя вообще. Новые товары/номера тоже не хардкодь — они живут в базе и управляются командами.
7. **МИГРАЦИИ.** Новая колонка = правка `init_db()`: добавь колонку в CREATE TABLE **и** в цикл ALTER TABLE по образцу существующих. Иначе у реального бота со старой базой всё упадёт. Новая таблица = CREATE TABLE IF NOT EXISTS в `init_db()`.
8. **ПОРЯДОК ХЕНДЛЕРОВ.** aiogram проверяет хендлеры в порядке регистрации. Новые команды — в секцию команд (до menu_buttons). Новые state-хендлеры — рядом с их FSM-секцией. НИЧЕГО после `fallback`.
9. **БЭКАП.** После любого изменения данных в базе вызывай `schedule_bg(backup_db_to_r2())`.
10. **КНОПКИ МЕНЮ.** Новая кнопка = константа BTN_*, добавить в MENU_BUTTONS, в `main_menu_kb()` (в правильную роль!) и ветку в `menu_buttons`.
11. **ОШИБКИ ПОЛЬЗОВАТЕЛЮ.** Не давай боту молчать: на неверный ввод отвечай подсказкой. Не ври об успехе: если отправка не удалась — скажи честно (см. save_and_send_report).
12. **НЕ ТРОГАЙ БЕЗ ПРОСЬБЫ:** структуру файлов, формат callback_data ("item:<id>", "confirm_inventory", "room_overwrite", "room_abort"), тексты, которые я не просил менять, r2_storage.py, планировщик.
