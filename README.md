# 🏨 Minibar Bot

Telegram-бот для учёта мини-баров в отеле. Горничная проверяет номер за 30 секунд: вводит номер комнаты, отмечает выпитое кнопками, отправляет фото — отчёт автоматически уходит в рабочий чат, а супервайзеры в любой момент видят сводку, сумму к оплате гостем и выгружают Excel для склада.

Интерфейс двуязычный: грузинский + русский.

## Возможности

- ⌨️ Главное меню кнопками (у каждой роли — свои кнопки), команды набирать не обязательно
- 📋 Пошаговая проверка номера: статус (🟢 заполнен / 🟡 не заполнен / 🔴 пустой / 🚧 out of order), выбор выпитого по каталогу, фото-подтверждение
- 🕳 В сводке по каждому номеру видно, чего не хватает (что доложить)
- 📤 Автоотчёт в рабочий чат: кто проверил, когда, что израсходовано, сумма к оплате гостем + сводка и сколько номеров осталось
- 💰 Цены товаров: бот сам считает сумму по каждой комнате (для ресепшена)
- 📊 `/export` — Excel-отчёт смены: «Номера» (с суммами) и «Пополнение склада» (с деньгами)
- 🕳 `/remaining` — какие номера ещё не проверены (по списку номеров отеля)
- ⏰ Автоматизация: вечером бот сам шлёт Excel в чат, утром закрывает смену (архив + очистка)
- 🗂 `/history` — история закрытых смен и самые ходовые товары
- 🏆 `/stats` — кто сколько номеров проверил за смену
- 📷 `/photos` — все фото смены альбомом
- 🛒 Каталог и цены хранятся в базе — меняются командами, без правки кода
- 🔁 Защита от случайной перезаписи уже проверенного номера
- ☁️ Автобэкап базы и фото в Cloudflare R2; при рестарте сервера данные восстанавливаются
- 🚨 Критичные ошибки приходят админам в личку
- 🔐 Команды супервайзеров и админа защищены по Telegram ID

## Команды

Все основные действия продублированы кнопками главного меню — оно появляется под строкой ввода. Команды тоже работают.

**Для всех:**

| Команда | Что делает |
|---|---|
| `/start` | Начать проверку номера |
| `/cancel` | Отменить текущую проверку |
| `/help` | Инструкция (каждый видит свои команды) |
| `/status` | Сводка по всем номерам со счётчиками |
| `/remaining` | Какие номера ещё не проверены |
| `/myid` | Свой Telegram ID (и ID чата — для настройки) |

**Для супервайзеров** (`SUPERVISORS_IDS`):

| Команда | Что делает |
|---|---|
| `/audit 605` | Детали, сумма и фото по номеру |
| `/product` | Сколько продукции осталось в номерах |
| `/export` | Excel-отчёт смены |
| `/stats` | Кто сколько номеров проверил |
| `/photos` | Все фото смены альбомом |
| `/history` | История закрытых смен + топ товаров |
| `/catalog` | Текущий ассортимент и цены |

**Для администратора** (`ADMIN_IDS`):

| Команда | Что делает |
|---|---|
| `/clear` | Закрыть смену: история + архив в R2 + очистка (подтверждение — напишите слово `УДАЛИТЬ` или `წაშლა`) |
| `/additem Red Bull 2` | Добавить товар (эталон — 2 шт в номере) |
| `/setqty Wine 2` | Изменить эталонное количество |
| `/setprice Wine 25.50` | Задать цену в лари (0 — убрать цену) |
| `/renameitem Старое \| Новое` | Переименовать товар (данные смены обновятся) |
| `/delitem Red Bull` | Убрать товар из каталога |
| `/setrooms 601-612, 701-712` | Задать полный список номеров отеля (для `/remaining`) |

## Установка и запуск локально

```bash
git clone https://github.com/nakkz0r/Minibar_bot.git
cd Minibar_bot
pip install -r requirements.txt
copy .env.example .env    # Windows (на Mac/Linux: cp .env.example .env)
# заполнить .env своими значениями
python bot.py
```

В логах должно появиться `Starting Telegram Bot polling...`

## Настройка .env

| Переменная | Что это | Где взять |
|---|---|---|
| `BOT_TOKEN` | Токен бота | [@BotFather](https://t.me/BotFather) → `/newbot` (или `/mybots` → API Token) |
| `REPORT_CHAT_ID` | ID рабочего чата для отчётов | Добавьте бота в группу и отправьте там `/myid` — ID группы отрицательный |
| `ADMIN_IDS` | ID администраторов через запятую | Напишите боту `/myid` в личку |
| `SUPERVISORS_IDS` | ID супервайзеров через запятую | Так же |
| `SUPERVISORS` | Юзернеймы для упоминания в отчётах | Просто текст, например `@anna, @tamari` |
| `AUTO_REPORT_TIME` | Время автоотчёта Excel в чат (ЧЧ:ММ, Тбилиси) | Например `22:00`; пусто — выключено |
| `AUTO_CLEAR_TIME` | Время автозакрытия смены (ЧЧ:ММ, Тбилиси) | Например `06:00`; пусто — выключено |
| `R2_*` | Ключи Cloudflare R2 (необязательно) | См. раздел «Бэкапы» |

⚠️ **Никогда не вписывайте реальные значения в код или `.env.example`** — они попадут в git. Только `.env` (он в `.gitignore`) и переменные окружения хостинга.

Не забудьте добавить бота в рабочую группу, чтобы он мог слать туда отчёты.

## Первичная настройка после запуска (5 минут)

1. `/myid` в личке — получить свой ID → вписать в `ADMIN_IDS` и `SUPERVISORS_IDS`.
2. `/myid` в рабочей группе → ID группы в `REPORT_CHAT_ID`.
3. `/setrooms 601-612, 701-712` — задать список номеров отеля.
4. `/setprice Wine 25` и т.д. — задать цены (по желанию; без цен бот просто не показывает суммы).
5. `/renameitem Cola Clasic | Cola Classic` — починить опечатку в каталоге (по желанию).
6. В `.env` задать `AUTO_REPORT_TIME` / `AUTO_CLEAR_TIME`, если нужна автоматизация смены.

## Как устроена смена

1. Персонал проверяет номера через `/start`; каждая проверка сразу уходит отчётом в чат.
2. Вечером (`AUTO_REPORT_TIME` или `/export`) — Excel-отчёт со всеми номерами и списком пополнения.
3. Утром (`AUTO_CLEAR_TIME` или `/clear`) смена закрывается: итоги записываются в историю (`/history`), база архивируется в R2 (`backups/…`), список номеров очищается для новой смены.

Каталог, цены, список номеров отеля и история при закрытии смены **не** стираются.

## Деплой на Render

1. Запушьте репозиторий на GitHub (лучше приватный).
2. [render.com](https://render.com) → New → **Web Service** → выберите репозиторий. Render прочитает `render.yaml` автоматически; если создаёте вручную: Build `pip install -r requirements.txt`, Start `python bot.py`.
3. В **Environment** добавьте все переменные из `.env` (сам файл `.env` на сервер не попадает).
4. На бесплатном тарифе Render усыпляет сервис — заведите монитор на [uptimerobot.com](https://uptimerobot.com), который раз в 5 минут дёргает `https://<ваш-сервис>.onrender.com/health`.

Вместо Render подойдёт любой хостинг с Docker — в репозитории есть `Dockerfile`.

## Бэкапы (Cloudflare R2)

Бесплатного лимита R2 (10 ГБ) хватит с запасом.

1. [dash.cloudflare.com](https://dash.cloudflare.com) → R2 Object Storage → создайте bucket (например `minibar-bot-storage`).
2. R2 → Manage API Tokens → создайте токен с правами Object Read & Write.
3. Заполните `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`.

Что бот хранит в R2: актуальную базу `minibar.db` (обновляется после каждой проверки), фото проверок в `photos/`, архивы смен в `backups/` (создаются при каждом закрытии смены). Восстановить стёртую смену: в панели R2 скачайте нужный `backups/minibar_<дата>.db`, переименуйте в `minibar.db` и загрузите в корень bucket — при следующем рестарте бот её подхватит.

Без ключей R2 бот тоже работает, просто без облачных бэкапов (на Render это значит: рестарт сервера = потеря данных смены).

## Структура проекта

```
bot.py           # весь бот: сценарий проверки, команды, отчёты, планировщик, healthcheck
r2_storage.py    # синхронизация базы и фото с Cloudflare R2
requirements.txt # зависимости
.env.example     # шаблон настроек (без реальных значений!)
render.yaml      # конфигурация деплоя на Render
Dockerfile       # запуск в Docker на любом хостинге
CODE_REVIEW.md   # отчёт код-ревью с историей исправлений
GEMINI_PROMPT.md # готовый промт для доработки кода через ИИ (Gemini и др.)
```

## Доработка через ИИ

Хотите доработать бота с помощью ИИ-ассистента (Gemini, ChatGPT и т.п.)? Откройте `GEMINI_PROMPT.md`, скопируйте промт в начало диалога, приложите `bot.py` и `r2_storage.py` — и только потом пишите свою задачу. Промт объясняет ассистенту архитектуру, схему базы и железные правила, чтобы он не сломал работающий код.
